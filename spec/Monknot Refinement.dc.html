Monknot

Interface refinement — design system & screens

Calm, quiet, native macOS chrome. One row primitive at 30/10/15/8/13 serves tabs, sidebar files, menus and results alike; five radii and a capsule replace the ten in the build; every glyph, gap and box comes off a stated ratio rather than a judgement call. Depth follows what a surface is, not which mode is on — docked chrome separates by tone and one hairline, resting cards draw a ring and never cast, and only genuinely floating layers get a shadow, in both modes. Tabs are inset chips in the 44px titlebar; the workspace name lives only in the sidebar. Switch themes below — every surface, shadow and hairline re-derives from CodexThemeCatalog, so try a light preset to see the other half of the depth system.

Audit

Nine fixes that define this pass

  1. Kill duplicate identity — filename no longer sits in the titlebar centre and again as a tab. Tabs are the document identity; workspace name lives only in the sidebar header.
  2. Outline becomes a rail — not a 214px docked panel. A 34px right-edge rail plots one dash per heading at its position in the document — length encodes level, so the rail is structure and scroll map at once. Hover peeks a charcoal card; chevrons step heading to heading. It needs no toolbar button, and ⇧⌘O remains the named, keyboard-reachable list.
  3. Toolbar zones — traffic + sidebar toggle + back / forward · tabs · flex · view mode · terminal panel. Two affordances right of the tabs and nothing else — no overflow menu. Outline, export, share and print left the toolbar entirely: the rail covers outline, the rest are menu commands. Icon buttons 28×28 with a 17px glyph at 1.5 stroke and 120ms hover.
  4. Sidebar density — 30px rows on the same primitive as a tab, consistent indent, selected = --sel + accent icon. Footer is Settings only; Recents collapses quietly.
  5. One overlay component — Quick Open and Go to Heading share 560px width, hug content height, identical empty and no-match patterns.
  6. Search owns its scope — Replace All is a real button; the confirmation sheet restates effect, never asks new questions.
  7. PDF progressive disclosure — colour and thickness appear only for tools that use them. “Select text first” is an inline hint, not a modal.
  8. Settings: instant apply + Revert — category sidebar, grouped rows with hairlines, never a Save button.
  9. Feedback triad — banner (soft equal fill), toast (auto-dismiss), sheet (destructive). No one-sided border error cards in chrome.

2dStrip geometrywidth, scroll, reveal, and the one case that still truncates
Width — hug, then cap
A tab is as wide as its contents: 10 + 15 + 8 + label + 18 close slot + 10, so a short name gives a short tab. The only limit is a 220px cap. Nothing ever shrinks to make room — a tab is the same width when twelve are open as when two are. The close slot is reserved at all widths so nothing shifts when the pointer enters.
Scroll — one axis, never stolen
The strip is a horizontal scroller. Two-finger horizontal and ⇧-wheel scroll it; a plain vertical wheel over the titlebar does nothing and must not be forwarded to the document. Momentum and rubber-band come from the platform scroller — do not reimplement them. No scrollbar is drawn; the strip is 30px tall and a bar would eat a third of it.
Reveal — nearest edge
Activating, opening or restoring a tab scrolls it just inside the visible strip by the nearest edge, plus one 3px gap. Never centre it: re-centring moves every other tab under the pointer, so the tab you meant to click next is somewhere else. If the tab is already fully visible, nothing scrolls.
Edge fade — the whole affordance
24px linear fade to --sidebar, present on a side only while content remains that way, cross-fading over 120ms. It is pointer-events:none so the tab under it stays clickable. There is no overflow count, no chevron, no menu — the count of open tabs is not information the titlebar owes you, and a menu was a second gesture to reach something a flick already reaches.
Truncation — only at the cap
A name only truncates when it alone exceeds 220px. Then middle-elide the basename and keep the extension whole: improving…ate.md. Head says what it is, tail says which one — tail truncation makes Untitled 4 and Untitled 5 identical. Two tabs that would still render the same label get the minimal distinguishing parent folder, and only those two. Ellipsis is U+2026, never three periods.
Pinned
Pinned tabs sit left of the unpinned run and scroll with everything else — they are not sticky. Pinning is about order and persistence across sessions, not about staying on screen.

This replaces the elastic-width ladder. Three compression tiers, a 144px floor, an LRU overflow menu and a count pill were four mechanisms solving a problem one scroller solves, and they all had the same defect: the tab you were reading changed size or vanished because you opened something unrelated.

⌘+ / ⌘− / ⌘0 move one factor that every metric in the window is derived from — titlebar, tabs, sidebar rows, glyphs, outline rail and body text together, the way VS Code and Xcode do it. Zooming only the text is the common mistake: 130% body under a 44px titlebar makes the chrome look like it belongs to a different app. PDFs are the exception — a page has a true size, so ⌘+ over a PDF zooms the page and leaves the workspace alone.

Rules

Implementation spec — read this before building

Every number below is normative. Colours are never literals: derive them from the active AppTheme so all 26 presets work without per-theme patches.

Colour derivation — from AppTheme
--bgtheme.background, verbatim. Document canvas only.
--sidebarmix(background → foreground) at 7.5% when the theme is dark, 2.8% when light. Sidebar, titlebar, tab strip, footers.
--surf2 / --surf3same mix at 11% / 17% (dark) and 5% / 9% (light). surf2 = popovers, overlays, sheets, peek cards; surf3 = fields and wells inside them.
--ink rampforeground at 100 / 62 / 40 / 24%. Four steps, nothing between. 24% is disabled only — never an idle control.
--accentpalette[4]. One accent per theme; no second hue for emphasis.
--selmix(background → accent) at 28% dark / 20% light. The single selection treatment app-wide.
--hover / --pressforeground at 6% / 11%. Every interactive surface uses this pair.
danger / oksemanticColors.diffRemoved / diffAdded, at 12% fill and 22% border for banners. Never a hardcoded red.
dark vs light testrelative luminance of background < 0.45 → dark mixes. Do not branch on the preset id.
Metrics — compact density
Titlebar44px. Contains traffic lights, sidebar toggle, the tab strip, view mode, terminal, ⋯. No separate tab bar and no centred document title.
Tab30px tall rounded chip inset in the 44px bar — radius 8, 10px horizontal padding, 8px gap, icon 15px, 3px between chips and no dividers at all. Active chip = --surf2 fill + --e1; idle transparent; hover --hover. Dividers between tabs are what made the old bar read as a grid of boxes; the chip carries the same information with no lines.
List / sidebar row30px, radius 8, 10px padding, 2px between rows, 6px list gutter, 16px indent per depth, 15px icon, 8px gap, 13px label — identical to a tab, on purpose. Selection is a full-width rounded fill inside 8px pane padding — never edge-to-edge.
Icon button28×28, radius 8, 17px glyph (60% of the box), 1.5 stroke, 2px gap inside a group, 10px between groups. The glyph grew and the stroke thickened together — a 16px glyph at 1.4 goes thin and grey at Retina scale, which is most of why the old bar felt weak.
Field / push button28 in bars and banners, 30 in sheets. Radius 8. Two heights, no third.
Radii2 indicator · 6 nested cell · 8 every control · 12 container, popover, menu, toast, panel, window · 16 sheet · capsule for pills and toggles. Five values and a capsule; child = parent − 4, floor 6. Nothing is squarer than 6.
Spacing steps2 4 6 8 12 16 20 24. Pane padding 12. Group gap 20.
Type20/600 window title · 15/600 group · 13/400 label · 12/400 row · 11/400 caption · 10/600 .08em eyebrow · 12.5 mono editor.
Proportion — every ratio, so nothing has to be eyeballed
The row primitiveOne row, reused everywhere: 30px tall · 10px padding-x · 15px glyph · 8px gap · 13px label. The file tab, the sidebar row, the overlay result row, the menu row and the outline peek row are all this row. They were five slightly different rows before, which is exactly why a sidebar file read as smaller than a tab holding the same filename — same content, different numbers. If two rows can appear on screen at once and hold the same kind of thing, they resolve to identical values or the interface looks miscalibrated.
Glyph beside a labelglyph = label + 2px, a ratio of about 1.15. 13px label → 15px glyph. 12 → 14. 11 → 13. At 1.0 the icon reads as an afterthought — it optically sits below the cap height and the row looks unbalanced. Past 1.3 the icon starts leading and the name becomes its caption. Round to odd px so the 1.5 stroke lands on a pixel boundary.
Gap, glyph to labelgap = label × 0.6, rounded even: 13 → 8, 12 → 7, 11 → 6. The gap is always smaller than the glyph it follows, so glyph and label group as one object. When the gap equals or exceeds the glyph they read as two separate things and the row loses its left edge.
Icon-only buttonglyph fills 60% of the box: 17 glyph in a 28 box (0.607), 16 in 26 (0.615), 15 in 24 (0.625). Below 55% the button looks empty and its hover fill reads as a stray rectangle; above 70% the glyph crowds the corners and the radius stops reading. This is the one place the glyph is not tied to a label — there is no label — so the box sets it.
Row heightheight = label × 2.3, rounded even: 13 → 30, 12 → 26, 11 → 22. That leaves 8.5px of clearance above and below a 13px label, which is the point where a 30px row stops feeling like a button and starts feeling like a line of a list.
Row padding-xpadding = height ÷ 3, rounded even: 30 → 10, 26 → 8, 22 → 7. Left and right are always equal. The trailing slot (close, count, dirty dot) sits inside the padding, never instead of it.
Secondary glyphsA close, chevron or disclosure glyph is primary glyph − 4: 15 → 11. Its hit target is glyph + 5: 11 → 16. A dot indicator is glyph ÷ 2.5 → 6. These are deliberately not on the label ratio — they are not content, and sizing them like content is how a tab ends up with three things all claiming to be the subject.
Bar and dividerA divider inside a bar is bar height × 0.36 tall: 16px in the 44px titlebar, 13px in the 36px panel header. Never full height — a full-height rule turns a bar into a table. A bar's own height is row height + 14, which is what puts a 30px tab in a 44px titlebar with 7px of air on each side.
Where the ratios stopEditor body text, PDF page content and empty-state illustration are not chrome and do not follow any of this. Everything from the window rim inward to the document does.
Zoom — one factor, the whole workspace
What zooms⌘+ / ⌘− / ⌘0 change workspaceZoom, and every metric in the window is a function of it: titlebar, tab chips, sidebar rows, glyph point sizes, gaps, paddings, radii, outline rail width and dash lengths, and all document text. Chrome and content move together. Zooming only the body text is the usual mistake — 125% prose under an unchanged 44px titlebar makes the chrome look borrowed from another app.
Steps, not continuous0.8 · 0.9 · 1.0 · 1.1 · 1.25 · 1.5 · 1.75 · 2.0. Discrete steps so every zoom level has been seen by someone; a continuous slider guarantees levels where a 13pt label rounds to 13.4 and every row in the sidebar sits on a different subpixel. ⌘0 returns to 1.0. The level is per window and persists per workspace.
PDF is the exceptionA PDF page has a true physical size, so over a PDF ⌘+ zooms the page and leaves the workspace alone. The chrome around it stays at the workspace factor. Zoom level is therefore two independent values, and the status bar shows whichever one the focused view owns.
Never scaleEffectDerive every number and lay out normally — never wrap the window in .scaleEffect(zoom). scaleEffect rasterises text at 1× and resamples it, so labels go soft; it scales the 1px hairlines into 1.25px grey smudges; and it leaves hit rectangles at their unscaled size, so buttons stop matching where they look. This is the single most common wrong implementation of app zoom.
RoundingBox metrics round to whole points: h = round(30 * z). Type rounds to the nearest half point: size = round(13 * z * 2) / 2 — SF Pro has real optical sizes and a half point is the finest step that still lands cleanly. Round once, at the point of use, from the base number in the scale table; never chain roundings (round(round(30*z)/3) drifts).
What does not scaleTraffic lights (the system owns them). The window corner radius. Every 1px hairline — --line, --line2, --frame and the elevation rings stay one device hairline at every zoom, because a border is a boundary rather than an object. Shadow blur and offset stay fixed for the same reason. Focus rings stay 3px.
Titles stay in proportionThe document h1 is 22pt at 1.0 and scales with the same factor, so the ratio between the window title, the tab label and the body text is constant. Nothing is clamped: a clamped element is exactly what makes a zoomed interface look unbalanced, because it silently changes the proportion the eye is using to judge everything else.
Outline rail under zoomRail width, dash lengths (22/14/9) and the gap between dashes all scale; dash thickness stays 2px. The peek card scales as a normal surface. The rail keeps mapping the whole document at every zoom, so it stays a scroll map rather than a list that runs off the bottom.
Minimum at 80%At 0.8 the row is 24pt, the glyph 12pt and the label 10.5pt — the floor. Below that macOS hit-target guidance breaks before the type does, which is why the scale stops there rather than at some smaller type size.
SF Symbols — size, alignment and spacing, unambiguously
Point size, not frameSize a symbol with .font(.system(size: s, weight: .regular)) and let it lay out at its intrinsic size. Do not use .imageScale — small/medium/large are relative to the surrounding font and give you three different results in three different rows. Do not set .frame(width:height:) on the symbol itself; that squashes glyphs whose aspect is not square.
The two sizesBeside a label: size = label + 2 — 15pt symbol next to a 13pt label. Alone in a button: 17pt in a 28pt button. Both scale by the zoom factor. Weight is .regular everywhere; .medium on a 15pt symbol reads as a different icon set two rows down.
Fixed glyph columnEvery symbol beside a label sits in .frame(width: 18 * z, alignment: .center). SF Symbols have different intrinsic widths — folder is wide, doc.text is narrow, doc.richtext narrower still — so without a fixed column the label's left edge moves from row to row, which is exactly why the current sidebar reads ragged. The box is 18 because the widest glyph in the set at 15pt is 17.4pt.
Vertical alignmentCentre the symbol on the label's cap height, not its baseline. In SwiftUI: put symbol and label in an HStack(alignment: .firstTextBaseline) only if you then apply .alignmentGuide with an offset of about -1pt * z; simpler and more reliable is HStack(alignment: .center) with both inside a fixed-height row, which is what the 30pt row already gives you. A baseline-aligned symbol sits visibly low, because SF Symbols are drawn centred on the cap-height band rather than on the baseline.
Horizontal spacingHStack(spacing: 8 * z) between the glyph column and the label — measured from the column edge, not the glyph edge, so the gap is identical regardless of which symbol is in it. Never rely on the symbol's own side bearing.
Optical adjustmentTwo symbols need a nudge because their ink is off-centre in their box: chevron.right in a disclosure control moves 0.5pt right, and magnifyingglass moves 0.5pt left. Nothing else. Do not eyeball others.
The symbol setsidebar.left · chevron.left / chevron.right · line.3.horizontal (source) · eye (preview) · sidebar.right · folder / folder.fill when selected · doc.text for markdown · doc.richtext for PDF · terminal · xmark for close · plus · gearshape · list.bullet.indent for the outline peek · clock for recents. Use the outline (non-fill) variant everywhere except a selected folder.
When SF Symbols will not doTwo cases. The outline rail dashes are not glyphs at all — draw them as 2pt rounded Capsule() shapes, since no symbol encodes heading depth. The file-kind badge for an unknown extension: SF Symbols has no generic-with-extension glyph, so draw doc and overlay the extension in 7pt SF Mono rather than hunting for a symbol. Everywhere else, a custom glyph will look imported — SF Symbols carry the system's stroke contrast and terminal shapes and a hand-drawn 15pt icon beside them always reads as foreign.
Rendering mode.symbolRenderingMode(.monochrome) with .foregroundStyle from the ink ladder. Never hierarchical or palette in the chrome — multi-tone symbols introduce a second grey that is not in the ladder, and against --ink3 at rest it reads as a rendering bug.
Buttons — padding, glyph, and every hover state
Icon-only button28 × 28 box, radius 8, 17pt symbol centred — no padding value, the box and the centring do it. At rest: no fill, 1px --line border, --ink2 glyph. Hover: --hover fill, --ink glyph, border unchanged. Pressed: --press fill. On (panel open): --accsoft fill, --accent glyph, and still only the --line border — no accent ring. Disabled: 40% opacity, --ink4 glyph.
No double edge on activeAn active icon button gets fill and glyph colour only. It does not swap its border to --accent: the button already sits in a bordered shell or beside one, so an accent stroke reads as a second, brighter rim around an already-outlined box — the blue ring effect. Fill is the state; the border is structure and never changes with state.
Text push buttonHeight 28 in a bar, 30 in a sheet. Horizontal padding 12, radius 8, label 13/400. Secondary: --surf3 fill, 1px --line, --bezel seat. Primary: --accent fill, --onaccent label, no border and no bezel. Destructive: --danger fill, white label. Hover lightens the fill by one step; it never changes padding, size, weight or elevation.
Button with glyph and labelPadding 10 leading / 12 trailing — asymmetric on purpose, because the glyph's own side bearing adds optical space on the left. Glyph 15 in an 18 column, gap 8, label 13. Same as a row, by design.
Segmented cellCell 28 × 22, radius 6, 16pt symbol, 2px gap between cells, 2px shell padding, 1px --line shell, no track fill. Selected: flat --sel + --ink glyph, no shadow and no border. Idle --ink2; hover --hover + --ink. The outer box lands on 28pt tall, matching every other control in the bar.
Markdown mode clusterThe three trailing controls read as one set because they share every number: 28pt tall, radius 8, 1px --line, 6pt between them. Left is the two-cell view-mode segmented (line.3.horizontal / eye); right is the terminal toggle. Nothing in the cluster has a fill except the selected segment and the toggle when its panel is open. If one of them ever needs a different height or a heavier border, it does not belong in the cluster.
Hover timing120ms ease on background-color and foreground only. Never animate size, position, elevation, border or weight. Hover fill appears on the whole 28pt box, not an inset — an inset highlight makes the target look smaller than it is.
Terminal session pill24pt tall, radius 8, padding 8, terminal symbol at 14 + gap 6 + session number in 12pt SF Mono. No session name. "zsh" on every pill is the same word four times; the number is what tells them apart. Run state tints the symbol: --ok running · --accent awaiting input · --ink3 idle · --danger exited non-zero. Close appears on hover and on the active pill.
Radius — one scale, five values and a capsule
2px — indicatorOutline rail dashes, scroll thumbs, progress fills, the find-match underline. Anything whose whole job is to be a mark rather than a container. Not 1px (reads as square at Retina), not 3px (reads as a lozenge).
6px — nested cellA cell inside a control: a segmented-control segment, a swatch inside a picker, a key cap in a shortcut field. Only ever appears inside an 8px parent.
8px — controlEvery standalone control, without exception: icon button, push button, text field, tab chip, sidebar row, list row, badge, segmented shell, popover row, stepper. If the user can click it and it is not a container, it is 8.
12px — container and floating layerCards, grouped lists, popovers, menus, toasts, the outline peek card, the terminal panel, and the window itself. Container and floating share one value on purpose: they are the same structural tier and giving a menu a different radius than a card it visually replaces makes the menu look like it came from another app.
16px — sheetModal sheets, dialogs and full overlay panels. The one tier above container, and the only radius that reads as "this is in front of everything".
Capsule999px for a toggle track and any pill; 50% for a dot. A capsule is not a radius choice, it is a shape — do not write half the height as a number, it silently breaks when the height changes.
Nesting rulechild = parent − 4, floor 6. A 12px card holds 8px rows; an 8px control holds 6px cells; a 16px sheet holds 12px cards which hold 8px rows. Never nest equal radii — concentric corners at the same value look like a rendering error — and never let a child be rounder than its parent.
Five values, total2 · 6 · 8 · 12 · 16, plus capsule. The build currently has ten, including 7, 9, 11, 13 and 18, which is the whole reason the corners look unresolved: 7 and 8 are indistinguishable individually but visibly wrong side by side, and 9 on a list row against 8 on a tab is the specific mismatch you can see in the titlebar. If a sixth value appears, it is a mistake, not a case.
Borders — every stroke in the app, and where none is allowed
--line — structural + control9% dark / 12% light of the ink hue. Two jobs. Structural: the sidebar, pane, titlebar and status-bar edges — docked surfaces earn no shadow, so if this line does not read there is no seam at all. Control: the border of a segmented shell, chrome icon button, text field and secondary push button. Dark runs lighter than light here because dark already has a luminance step doing the work and light has almost none.
--line2 — divider only6% dark / 8% light. Between rows of a grouped card, between blocks inside a popover, under a panel header. Always inset from the container edge so it never meets a corner radius, and never used as a structural seam — that substitution is why the sidebar edge currently disappears.
--frame — window rim14% dark / 9% light, one per window, drawn as the outer ring inside --win. Dark needs the definition its shadow cannot supply; light already has the shadow, so the rim only has to keep white from bleeding into white.
Elevation rings--e1/--e2/--e3 each carry their own inset 0 0 0 1px ring. This is not a border property and must not be paired with one — a declared border on top of an elevation token gives you a 2px rim, which is the doubled edge visible on the window mock before this pass.
Accent stroke1px --accent in exactly two places: a toggle button that is on (with --accsoft fill) and a field that has focus. Nowhere else. An accent outline around an active icon button is the most common wrong build of this system.
Focus ring3px --accent at 35% outside the control, in addition to the control's own border, never replacing it. It is drawn outside the layout box so nothing moves when focus lands.
No stroke allowedBetween segments of a segmented control — the 2px gap does it. Between tabs — the chip does it. Around an active icon button — the fill does it. On any hover state — a border that appears on hover reads as a jump even though nothing moved. On both a container and its first child at the same edge. On top of an elevation token. On a filled accent button.
Always a hairline1px logical, which is 0.5pt on Retina. Never 2px, never dashed, never a left-border accent stripe on a card, never inset and outset on the same element. If a boundary needs more presence than a hairline, it needs a tone step or a shadow, not a thicker line.
Toolbar — what is allowed in it
Zones, left to righttraffic lights + sidebar toggle + back / forward │ tab strip │ flexible gap │ view mode │ terminal toggle. Navigation leading, document actions trailing — the split Finder, Safari and Xcode use. Exactly two affordances right of the gap. There is no ⋯ overflow; anything that would land in one belongs in the menu bar, where macOS already indexes it for Help search.
Back / forwardNSSegmentedControl, trackingMode = .momentary, two image-only 28×22 cells, glyph 16, chevron.left / chevron.right, bound to ⌘[ and ⌘]. 1px --line shell, no track fill. Each segment disables independently when its stack is empty — it never disappears and the control never resizes.
View modeTwo cells: Source (three lines) and Preview (eye). 28×22 each, glyph 16, in a 1px --line shell with no track fill. Selected cell is a flat --sel fill with an --ink glyph — no shadow, because nothing inside a control floats. Idle --ink2, hover --hover + --ink. Tooltip carries the word.
Split is removedIt was a third state of a two-state choice. Source and Preview are a mode; a side-by-side editor is a window arrangement, which belongs to the Window menu with its own shortcut, not to a control whose other two cells switch how one pane renders.
Chrome buttonsSidebar toggle and terminal toggle: 28×28, radius 8, 1px --line, no fill at rest, --hover on hover, --accsoft + 1px --accent + accent glyph when the panel is open. They read as a set with the two segmented shells because all four now carry the same border and no fill.
Inline toolbar iconsThe format bar and PDF tool icons get no border — they already sit inside a bounded strip, so a border on each would double the line. 28×28, bare at rest, --hover fill on hover.
Disabled, not hiddenFor PDF and plain text the whole view-mode control drops to 40% opacity with --ink4 glyphs. Controls never appear or disappear between file kinds — the toolbar must not reflow.
Removed on purposeOutline, export, share, print and the ⋯ overflow are not in the toolbar. Outline is the rail; export, share and print are menu items with shortcuts (⇧⌘E, ⌘P).
CeilingNever more than two icon affordances right of the tab strip. Hitting the ceiling means the next command goes to the menu bar, not into the window.
Outline rail — full algorithm
Container34px wide, absolutely positioned on the right edge of the editor pane, top 0 bottom 0, above the text (z 5). It does not take layout width; text keeps its measure and the rail floats over the trailing gutter.
Dash y positiontop = (heading.characterOffset / document.length) as a percentage, translateY(-50%). Position therefore encodes where the heading sits in the document — the rail is a scroll map as well as an outline.
Dash lengthH1 22px · H2 14px · H3 9px · H4+ clamp at 9px. Right-aligned 10px from the pane edge, so all dashes share a trailing edge and the ragged left edge draws the hierarchy.
Dash paint1.5px tall, radius 1.5, --ink3 at 55% opacity.
Active heading--ink at 100%, 2.5px tall, +2px longer. Exactly one dash is active — the last heading whose position is above the viewport top.
Hover34×20px hit target fills --hover with radius 7 0 0 7. Dash goes to --ink at 90%. 120ms ease on width, height, opacity and background.
Peek card40px to the left of the rail, vertically centred on the dash, 244px wide, --surf3 fill, radius 16, no border, shadow 0 18px 44px rgba(0,0,0,.5), padding 13/17. Line 1 = parent context, 12px --ink3. Line 2 = heading text, 13.5px --ink, clamped to two lines. pointer-events none, fadeUp 160ms.
Chevrons13px, --ink4, 14px inset from top and bottom of the rail. Previous / next heading. Same hover target as a dash.
Click / dragClick scrolls that heading to the top with the pane's normal scroll animation. Dragging along the rail scrubs, updating the peek card live.
AccessibilityThe rail is an accelerator, never the only path. ⇧⌘O opens the named heading list; the rail itself is a listbox with aria-labels carrying the heading text, reachable and operable from the keyboard.
Empty stateFewer than two headings → hide the rail entirely. Never show a rail with one dash.
Overlays, feedback, sidebar
OverlayOne component for Quick Open and Go to Heading: 560px wide, 74px from the top of the content area, height hugs its rows, max 8 rows then scroll, --surf2 fill, radius 10. Same empty and no-match patterns; the empty state names the query and offers the next move.
BannerDocument state (disk conflict, removed file, read-only). Docks under the titlebar, full width, equal soft fill — no one-sided accent border. Actions right-aligned, at most one accent button.

SheetIrreversible choices. Restates the effect and lists what it touches; it never introduces a new choice the panel should have made.

Sidebar headerWorkspace name + disclosure chevron, 22px trailing actions (new file, search). The workspace name appears here and nowhere else.
Sidebar footerSettings only, above a 1px rule. Recents is a collapsed disclosure row in the list, not a section.
SettingsCategory sidebar (General, Appearance, Editor, Export, Shortcuts). Label left, help under the label, control right on one shared column. Instant apply; state and Revert live in the group header. There is no Save button.

Weight and colour — two weights, and never a bolder selection
Two weights, total400 for everything the user reads as content: every row, tab, pill, field, button label, body and help text — selected or not, hovered or not, focused or not. 600 for headings, group eyebrows and window titles. That is the whole vocabulary.
500 is goneIt used to mark the one active label in a set. It is removed. A label that thickens on selection reflows its own glyphs by a fraction of a pixel, so the row appears to twitch under the pointer, and running down a list makes the whole column breathe. It also reads as a permanent property rather than a reversible state. Any place the build still bolds an active tab, selected sidebar row, active terminal pill or selected segment is a defect.
Never bolder onHover. Selection. Focus. Press. Active. Current. If an item needs more presence it takes a fill plus one step up the ink ladder — that is the entire mechanism, and it is enough because fill is a much louder signal than weight.
Ink ladder--ink4 disabled · --ink3 glyph at rest and secondary text · --ink2 label at rest · --ink label or glyph when its row is hovered or active. Selection moves one step up this ladder and adds --sel; hover moves one step and adds --hover.
Accent, five placesThe active tab's kind glyph · the selected sidebar row's glyph · a dirty dot · a toggle button that is on · the terminal glyph of a session awaiting input. Nothing else in the chrome is coloured. If a sixth accent appears, one of these gives it up. Glyphs are never tinted by file type, folder or language.
Active button treatment--accsoft fill, 1px --accent border, --accent glyph. Not a heavier stroke, not a filled SF Symbol variant, not a ring.
Hover treatment--hover fill and the glyph one step up the ink ladder. Never a shadow, never a scale transform, never a border appearing, never a weight change.
Tooltips
AnchoringAnchored to the element, never to the pointer and never free-floating in the canvas. Positioned below the element, horizontally centred on it, 6px clear; flips above when there is no room below and shifts horizontally to stay 8px inside the window.
Look--surf3 fill, radius 8, --e2, 6px/9px padding, 12px/400 --ink, single line, no border, no arrow. Max 320px then it wraps to two lines.
WhenOnly where information is missing from the interface: a tab whose name is elided at the 220px cap (full workspace-relative path), any icon-only button (label plus shortcut), a terminal pill (the session name and run state the pill does not show). A tooltip that repeats visible text must not exist.
Timing500ms delay on first hover, 0ms while moving between siblings in the same strip, dismissed instantly on exit or any click. Fades in over 120ms with no movement — tooltips do not use fadeUp.
Observed build defects and the rule that prevents each
Terminal in the left columnThe panel was rendered below the sidebar in the 360px left column. It is a right-edge panel, 420 default / 320 min, full height, mirroring the left sidebar — see 2e. The prose that caused this has been corrected.
Oversized + and ✕Rendered at roughly a 28px glyph in a 40px box. They are 16px glyphs in 26px boxes and are the smallest controls in the app. See the scale table.
Terminal pill labelled “zsh” four timesFour sessions rendered four identical “zsh” labels, so the pills identified nothing and each cost 100px of a 333px strip. A pill is a fixed 43×24: terminal glyph tinted by run state, gap 6, session number in 12pt SF Mono. Being clipped by the panel edge is correct — the strip scrolls and the trailing pill sits under the fade.
Extension truncatedLabels read “Untitled 2.m” and “Untitled 5.m”. The extension is never truncated — middle-elide the basename instead. Tail truncation is forbidden precisely because it eats the extension and the disambiguating suffix.
Every tab the same width, all clippedEight tabs were laid out at one equal width and every label was clipped. A tab hugs its own name up to a 220px cap and never shrinks; when the tabs outrun the bar the strip scrolls horizontally with a 24px edge fade. Nothing is compressed and nothing is hidden behind a control.
Tooltip floating in the canvasThe tooltip appeared unanchored in the middle of the document. It anchors 6px below its element, centred on it.
Active state drawn as a box outlineThe active view-mode segment was drawn as a heavy rectangle outline. Active is --accsoft fill plus an --accent glyph — never an outline.
Stray control top-leftA mis-scaled coloured rounded rect sat left of the sidebar toggle. Nothing precedes the traffic lights, and the first control after them is the 28px sidebar toggle with 10px clear.
Tab strip — hug, cap, scroll
Geometry30 tall, radius 8, 3px between chips, strip inset 3px inside the 44px titlebar, no dividers. Content, left to right: 10 padding · 15 kind glyph · 8 gap · 13 label · 8 gap · 16 trailing slot · 10 padding.
WidthHug the label, cap at 220px. No minimum, no floor, no shrinking. A tab is the same width with thirty open as with two, so the strip the user learned stays put. The 16px trailing slot is reserved at every width, so nothing shifts when the pointer enters.
ScrollThe strip is a horizontal scroller. Two-finger horizontal and ⇧-wheel scroll it. A plain vertical wheel over the titlebar does nothing and is never forwarded to the document. Momentum and rubber-band come from the platform scroller. No scrollbar is drawn — the strip is 30px tall and a bar would take a third of it.
RevealActivating, opening or restoring a tab scrolls it just inside the strip by the nearest edge, plus one 3px gap. Never centre it: re-centring moves every other tab out from under the pointer. If it is already fully visible, nothing scrolls.
Edge fade24px linear fade to --sidebar on a side only while content remains that way, cross-fading over 120ms, pointer-events:none. This is the only overflow affordance in the titlebar.
TruncationOnly when one name alone exceeds 220px. Then middle-elide the basename and keep the extension whole (improving…ate.md) — head says what it is, tail says which one, and tail truncation would make Untitled 4 and Untitled 5 identical. Two tabs that would still render the same label get the minimal distinguishing parent folder, applied only to those two. Ellipsis is U+2026. The app computes the elided string; the label never carries text-overflow:ellipsis, because CSS can only clip the tail and would append a second ellipsis to a string that has already been middle-elided, taking the extension with it.
Close11px glyph in a 16px round target, --ink3 → --ink on hover. Visible on the active tab and on hover; the reserved slot means it never changes layout. ⌘W closes the active tab; middle-click closes any tab.
PinnedSits left of the unpinned run and scrolls with everything else. Pinning is about order and session persistence, not about staying on screen.
Terminal pillsThe one place the row model does not apply. A session has no name worth reading — four pills all saying "zsh" identify nothing — so the pill is a fixed 43×24: terminal glyph at 14, gap 6, session number in 12pt SF Mono. No label, so no hug and no cap. Run state tints the glyph rather than adding a dot. The header strip still scrolls with the same 24px fade.
RemovedThree compression tiers, the 144px floor, the 38px condensed chip, the LRU overflow list, the hidden-count pill and the overflow menu. Six mechanisms for what one scroller does, all sharing one defect: the tab you were reading changed size or disappeared because you opened something unrelated.
Tab tokens and icon colour — no literals anywhere
Chip fillActive --surf2 + --e1 · hover --hover · idle transparent. Never --sel — that is list selection and reusing it makes a tab look like a sidebar row. Never --accent as a fill: accent marks state, it is not a surface.
LabelActive --ink at 500 · idle --ink2 at 400 · dimmed shared prefix --ink3 · 13px in file tabs, 12px in terminal pills. The weight change from 400 to 500 is doing as much work as the fill — keep both.
Kind icon — the one accent moment15px, 1.5 stroke, outline SF Symbol. --ink3 idle, --ink2 on hover, --accent on the active tab only. This is the single use of accent in the strip; colouring every tab’s icon, or colouring by file type, destroys it. File type is carried by glyph shape, never by hue.
Which glyphdoc.text markdown and text · doc.richtext PDF · chevron.left.forwardslash.chevron.right in a doc frame for HTML and JSON · pin.fill pinned · xmark close · plus new. Filled variants only for the pin, which needs mass at 12px.
Dirty dot6px, --accent, always. Not red — unsaved is a state, not an error, and semanticColors.diffRemoved is reserved for destruction.
Terminal run stateThe terminal glyph is the only coloured element in a pill, and its tint is the run state: --ok running · --accent awaiting input · --ink3 idle or exited 0 · --danger exited non-zero. These four are the same four everywhere in the spec. The session number stays --ink2 regardless, so a strip of pills reads as a row of status lights rather than coloured text.
Light modeThe active chip needs --e1’s 0.5px ink ring to separate --surf2 from the light titlebar — without it the chip disappears. Inactive tabs get no fill at all; the kind glyph and label carry them against a light bar.
Dark modeThe chip rides the --bg→--surf2 luminance step plus --edge. --e1’s ring is invisible here and that is correct — do not compensate by adding a border, which is what made the old strip read as a grid of boxes.
NeverNo borders on tabs in either mode, no underline on the active tab, no gradient, no per-file-type colour, and no shadow on hover — hover changes fill only.
Depth — the surface class decides, not the mode
What Codex doesRead off the two builds side by side: the sidebar has no shadow in either mode; the reply card sits on a hairline with no shadow in either mode; the menu and the window have a real shadow in both. Nothing in the chrome is ambiguous about whether it floats. The variable is not light-vs-dark, it is what the surface is.
Three classesDocked — sidebar, titlebar, tab strip, inspector, status bar. Fills the edge, cannot move. Contained — cards, grouped rows, fields, tab chips, the composer, sidebar selection. Sits inside a region and scrolls with it. Floating — menus, popovers, toasts, peek cards, sheets, windows. Detached from the layout, dismissible. Assign the class first; the treatment follows from it.
Docked — never a shadowTone step plus one hairline (--line), full stop. A sidebar is not hovering above the canvas, so a shadow under it is a lie the eye catches immediately. The two modes split the work differently: dark has a large luminance step (canvas --bg to sidebar --sidebar) and the line only needs to hint at 9%; light has almost no step — near-white against white — so the line carries the seam and goes to 12%. This is the reverse of the usual instinct and it is why light chrome so often looks seamless and dark chrome so often looks over-ruled.
Contained — also no shadowA card at rest gets --e1, which is a 1px ring and nothing else in both modes: ink 12% in light, white 9% in dark. Light needs the ring because a white card on a white ground has no other edge. Dark mostly gets away on tone but keeps the ring so rounded corners stay crisp. Filled states — sidebar selection, a user message bubble, a hovered row — take neither ring nor shadow; the fill is the whole signal.
Floating — shadow, both modesOnly here does shadow appear, and it appears in both modes, because a shadow is what says dismissible. --e2 popovers, menus, toasts: light 0 4px 12px 8%, 0 1px 3px 5% + ring 8%; dark 0 8px 24px black 50%, 0 2px 6px black 34% + ring 14%. --e3 sheets and dialogs: light 0 16px 40px 14%, 0 4px 10px 6%; dark 0 24px 60px black 64%, 0 6px 16px black 40%. Dark shadows are larger and much darker — over a near-black ground a light-mode alpha simply disappears — and dark rings are stronger for the same reason. Always two layers: the tight key gives the edge, the wide ambient gives the lift, blur 2–3× the offset.
ControlsA push button is contained, not floating. Secondary and bordered controls get fill + --line + --bezel, where --bezel is 0 1px 1px 5% in light and none in dark — the one-pixel seat that makes a macOS bezel look pressable without looking raised. Accent-filled buttons take neither border nor bezel; the fill is enough. Toolbar icon buttons are bare at rest and gain only a --hover fill.
Shadow colourLight shadows are mix(foreground → accent, 10%), never pure black — black on a warm white goes muddy, and the 10% accent picks up the theme temperature with no visible cast. Alphas stay in the 5–14% band; past that a light shadow stops reading as shadow and starts reading as dirt. Dark shadows are plain black at 34–64%: there is no hue to preserve down there, only density.
Rings and bordersA surface gets exactly one ring per boundary. Popovers, sheets, toasts and tab chips never take a border property — the elevation token already draws it, and a declared border on top doubles the stroke. Windows use --win: the --e3 ambient with --frame as a single outer ring, because a window clips its content and its edge has to be drawn outside. --frame is 14% dark / 9% light — dark needs the definition its shadow cannot give, light already has the shadow. --line2 (6% dark / 8% light) is only ever an in-container divider, inset from the container edge, never a structural seam.
NeverNo shadow on anything docked. No shadow on anything at rest. No shadow stacked on a surface that already sits on a shadow. No inner top highlight — on a rounded card a single lit edge reads as a bevel. No elevation change on hover: hover changes fill, not height.
Typography & rhythm — the retuned scale

What changed and whyRow and tab text went 12 → 13 and labels 13 → 13.5. At 12px on Retina, SF Pro Text lands below its optical-size switch and reads as a caption; the app looked like a settings sheet rather than a document tool. Leading opened one notch with it (1.3 → 1.35, 1.5 → 1.55) so the extra size does not tighten the lines.
NumeralsAny value the user can step or that changes live — sizes, percentages, counts, page indicators, line numbers — is mono at 13px so digits never jitter as they change width.
WeightTwo weights only: 400 for all content — rows, tabs, pills, labels, body — selected or not, and 600 for headings and eyebrows. Weight 500 is gone from the chrome and nothing is ever bolder for being hovered, selected or focused. No 700 anywhere.
Vertical rhythm12px pane padding · 8px sidebar pane padding · 1px between list rows · 20px between setting groups · 6px between a group eyebrow and its card · 11/14px padding inside grouped card rows. Spacing steps stay 2 4 6 8 12 16 20 24.
Use the AppKit / SwiftUI component — do not rebuild it
Window shellNSSplitViewController with three columns: sidebar, content, and — when the terminal is open — nothing extra; the terminal lives inside the sidebar column. Set the sidebar item's behavior = .sidebar so macOS gives it the full-height translucent treatment and the automatic ⌘⌥S toggle.
Left sidebarApple's source list, unchanged: SwiftUI List(selection:) { OutlineGroup(…) }.listStyle(.sidebar), or AppKit NSOutlineView with style = .sourceList. Do not draw a custom list — the system supplies vibrancy, selection, disclosure animation, drag reordering, right-click menus, full keyboard traversal and VoiceOver for free, and it re-tints itself when the user changes their macOS accent.
Titlebar + toolbarNSToolbar with toolbarStyle = .unified and the tab strip as a centred custom item. The leading sidebar toggle must be the system .toggleSidebar item, not a hand-rolled button.
View modeNSSegmentedControl, .selectOne, segmentStyle = .texturedRounded, image-only segments with toolTip on each.
IconsSF Symbols only, weight .regular, scale .medium: sidebar.leading, sidebar.trailing, text.alignleft, rectangle.split.2x1, eye, doc.text, doc.richtext, folder, pin.fill, terminal. The SVGs on this board are stand-ins for these symbols — ship the symbols.
Sheets and alertsNSAlert for the one surviving unsaved-changes case; window-modal .sheet for Replace All. Settings is a Settings scene with .tabViewStyle replaced by a sidebar NavigationSplitView.
ControlsToggle, Slider, Stepper, Picker(.menu), NSColorWell. Every metric in the Metrics column above describes what these controls already measure at the small control size — they are a description of the system, not a replacement for it.
Where custom code is allowedOnly three things are genuinely bespoke: the outline rail, the tab strip inside the unified titlebar, and the peek card. Everything else has a system component.
What each of the three toolbar changes looks like, precisely
Back / forward restoredA two-cell segmented shell sitting 2px after the sidebar toggle, inside the leading group and before the 1px divider that starts the tab strip. Shell: --hover fill, radius 6, 2px padding, 2px gap — identical to the view-mode shell, because both are the same AppKit control. Cells are 26×22, radius 4, holding a 15px chevron at 1.5 stroke. Enabled cell is --ink2, going --ink on a --press fill on hover; a cell whose history stack is empty sits at --ink4 with no hover response. The board shows the common real state — back live, forward spent. Momentary, so neither cell ever holds a selected fill; that treatment belongs to view mode alone.
⋯ removedThe 26×26 button that sat furthest right in the titlebar is gone — not disabled, not hidden behind a condition. The 1px --line divider that preceded it goes with it. The trailing edge of the titlebar is now 12px of padding after the last icon. Nothing reflows when the document kind changes, because the two remaining affordances exist for every kind.
Terminal button glyphSame 26×26 button in the same position; only the glyph changes. It was a terminal window with a chevron-and-underscore prompt; it is now sidebar.trailing — a 12.8×10.8 rounded rect, 2px corner, with a full-height vertical rule 10px from the left edge and two short horizontal strokes (3.4px and 2.2px) in the larger left region. 1.4 stroke, --ink2 at rest, --ink on hover over a --hover fill, and when the panel is open the button takes the active treatment: --accsoft fill with an --accent glyph at 1.5 stroke.
Why that glyphThe button no longer advertises “terminal”, it advertises “reveal the panel on that side” — which is what it does. It mirrors the leading sidebar.leading toggle at the other end of the titlebar, so the two ends of the bar read as a matched pair and the user learns one idea instead of two.
The terminal itselfUnchanged in every respect — same shell, same session model, same output rendering, same tab behaviour. The only thing this board changes is where its toggle lives and what the toggle looks like. It opens as a panel on the right edge of the window, mirroring the left sidebar: same --sidebar surface, same 1px --line2 separator (on its leading edge), full height from under the titlebar to the bottom of the window. It is NOT below the sidebar, NOT inside the left column, and NOT a bottom drawer. See 2e for the anatomy at size.
